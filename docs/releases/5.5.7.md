# oxidize-pdf 5.5.7

This patch release fixes explicit Identity ToUnicode decoding and reduces
repeated font-data copies, operator-buffer allocations and duplicate object
storage. Public API signatures, external dependencies and Rust 1.88 remain
unchanged.

## Identity ToUnicode compatibility

Type0 fonts with explicit `/ToUnicode /Identity-H` or `/Identity-V` names are
accepted, including indirect names, in strict and lenient modes. Unicode text
is decoded consistently by text extraction and the resolved-font API (#851).

UTF-16 surrogate pairs are combined only within one text-showing byte slice.
The resolved-font API retains both source glyphs, CIDs, GIDs and advances: the
first glyph carries the scalar and the second carries an empty Unicode string.
An Identity encoding alone is not treated as proof of a Unicode mapping;
unsupported names and malformed input retain their existing error/recovery
contracts. This is a compatibility correction, not a new PDF conformance claim.

## Performance and memory

Parsed font data is shared immutably across pages and Form XObjects. Small
operator buffers are reused when switching text/graphics contexts; large
buffers are released. Parsed objects are stored once in the reader, and
objects returned to callers still own independent data (#854).

On the documented Linux/i7-3770 workloads, 25 paired samples showed:

| Workload | Paired median reduction |
| --- | ---: |
| Text extraction, synthetic shared-font document | 86.4% time |
| Mixed text/graphics generation, compressed | 5.5% time |
| Mixed text/graphics generation, uncompressed | 11.1% time |
| Peak RSS, 256-page large-stream document | 46.6% memory |

**Tradeoff:** traversal/hash time for the 256-page stream workload increased
4.5% (95% bootstrap interval: 2.1–7.0%). Text-only and small-generation controls,
and the real-document extraction control, did not show a conclusive timing
change. These results are not a promise of improvement for every PDF or machine.

The [benchmark and review report](../reports/2026-11-06-issue-854-review.md)
records inputs, raw samples, variability, equivalent generated content and the
excluded invalid comparison. Benchmarks measured the pre-version-bump sources;
the release preparation changes metadata and notes only, not product logic.

## Validation and scope

The Identity mapping and storage changes have behavioral regression tests for
Unicode, geometry, ownership, generation errors and painting order. The coverage
follow-up also tests pending text before a TextFlow and repeatable serialization;
Codecov reported 49/49 changed product lines covered on the validated #855 head.
This is patch coverage, not 100% coverage of the library.

The existing release gates verify the exact candidate and published package.
Publishing this Rust crate does not release Python/.NET bindings or complete
bridge parity (#710); those remain separate work.
