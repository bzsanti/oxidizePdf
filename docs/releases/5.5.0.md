# Core 5.5.0 release candidate

Preparation issue: [#787](https://github.com/bzsanti/oxidizePdf/issues/787).
Baseline: published v5.4.2. Product source: develop c440d5bf9181b2b93f467870899e86479022dd9a.
This document describes a candidate, not a published registry artifact.

## Version decision

5.5.0 is a minor release: it adds public APIs for incremental edits, timestamp
preparation, typed calculation results and effective memory configuration while
preserving existing public signatures. A patch would understate these additions.
The AES `generate_iv()` wrapper retains its return type; callers can opt into
`try_generate_iv()` to handle entropy failures. Compatibility checks are evidence
for API compatibility, not a guarantee that every historical behavior is retained.

## Python and .NET migration

1. After publication, pin the published core 5.5.0 crate and record its checksum;
   rebuild and test each bridge and its supported platforms.
2. Expose typed field/calculation getters and transitive recalculation (#771), and
   verify inherited ReadOnly failures leave the input/output unchanged (#770).
3. Exercise attachment round trips including Unicode names, exact payload bytes
   and encrypted PDFs (#774).
4. Map effective configuration and unsupported-option diagnostics (#758). Do not
   advertise `LazyDocument` memory mapping or stream-content processing as active.
   Eager loading parses indexed objects; it does not eagerly decode all content.
5. Use worker memory limit `0` until a real cap exists. Nonzero values now fail
   explicitly. Batch timeout measures elapsed execution on return, cannot stop a
   running callback and cannot undo its side effects. With stop-on-error, already
   running parallel jobs may finish (#776).
6. Propagate unsupported-operation and permission errors. Legacy signature APIs,
   unavailable verification capabilities and unsupported dashboard operations
   no longer return fabricated success/results. Test the bridge's error mapping.
7. For WASM AES, enable getrandom 0.4's `wasm_js` backend in the application and
   test secure entropy in the deployment environment (#711).
8. Treat external timestamp preparation as container preparation: the caller
   supplies and validates the RFC3161 token and trust policy. Generic incremental
   edits retain their documented encryption and DocMDP/FieldMDP restrictions;
   this release does not provide TSA transport or a complete PAdES workflow (#714).

The complete feature/fix list is in [CHANGELOG.md](../../CHANGELOG.md).
The five core blockers #758, #770, #771, #774 and #776 are integrated; this does
not close the broader parity issue #710 or replace downstream acceptance tests.
OCR issue #708 remains open. Certificate recipient encryption #642 / draft PR
#658 is excluded; existing password-based AES support is a separate capability.

## Publication handoff

The preparation PR targets `develop`. After its checks pass and release approval,
merge the release into `main`, verify checks on the exact release commit, and tag
that commit `v5.5.0`. The tag triggers GitHub/crates.io publication. Verify registry
availability/checksum before downstream adoption. No tag or registry publication
is performed as part of preparing this candidate.
