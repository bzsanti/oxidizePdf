# oxidize-pdf 5.5.4

This patch release updates the optional signature verification dependency graph
to address RUSTSEC-2026-0387 in crypto-bigint. It requires oxidize-webpki 0.1.1,
ecdsa 0.17, P-256/P-384 0.14 and crypto-bigint 0.7.10 or later in the 0.7 series.
The explicit minimum prevents existing consumer lockfiles retaining an affected
version. No advisory suppression is introduced.

Signature verification APIs and supported algorithms remain unchanged. ECDSA
public-key decoding uses the upgraded provider's SPKI trait; RSA/CMS retain
their existing compatible dependencies. Rust 1.88 remains the minimum.

Independent OpenSSL vectors exercise P-256/P-384 SPKI verification with raw
messages and prehashes, rejecting wrong keys, altered inputs and signatures.
The signature unit tests and CMS/certificate integration tests cover existing
validation and rejection policies. This is a targeted dependency correction,
not a claim that every dependency is free of advisories.

Users enabling signatures should upgrade to this release. The previously
published 5.5.3 crate is immutable and does not contain this correction.
