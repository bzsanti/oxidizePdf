# oxidize-pdf 5.6.1

This patch release fixes strict parsing of indirect stream lengths and object
number allocation for compressed object streams. Rust 1.88 remains the minimum
supported version.

## Strict stream parsing

The public strict reader resolves an indirect `/Length` through the document's
cross-reference information, then reads the exact stream bytes. Valid indirect
lengths no longer require lenient mode. Invalid references, generations and
cycles return errors. Nested stream reads are bounded by available input and
representable capacity before allocation; this is not a global process-memory
limit (#875).

## Compressed object streams

The writer allocates object-stream IDs through the document's existing checked
allocator instead of starting at a fixed high number. This avoids sparse object
numbering rejected by external validators, including in incremental-update
validation (#880).

## Validation

Independent annotation and signature fixtures now include required page
resources. The regenerated DocMDP fixture retains a verifiable CMS signature
and ByteRange (#878). Coverage and interoperability use checksum-verified
qpdf 12.4.2. Zero-page output retains separate structural checks and corrupted
cross-reference negative controls; it is not presented as passing qpdf's
nonempty-document conformance check (#881).

Release acceptance is tracked in core issue #877. Publication requires the
official workflow, package identity verification and a clean registry consumer.
Python 0.24.1 and .NET 0.23.0 adoption are tracked separately in their respective
issues #317 and #129; the Rust release alone does not update installed bridges.
