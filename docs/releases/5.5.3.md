# Core 5.5.3

Release tracking: [#824](https://github.com/bzsanti/oxidizePdf/issues/824).
Baseline: published 5.5.2. This document prepares the release; publication is
established by the matching GitHub release and registry artifact.

## Corrections and compatibility

Indexed page access now uses the same recovered page tree as page counting.
An empty tree does not expose unrelated page objects through a fallback scan
([#817](https://github.com/bzsanti/oxidizePdf/pull/817)).

Tesseract OCR preserves Unicode, including Spanish diacritics, and returns
measured word boxes and confidence from TSV. Searchable text fits its requested
region at all four page rotations. Conversion follows painted image placements,
decodes image instances one at a time and bounds Form traversal. Providers using
legacy page-point coordinates retain their contract through an explicit
coordinate-space declaration. Unsupported visibility/compositing states return
errors. Existing Tesseract preprocessing and timeout options are not newly
implemented by this release
([#820](https://github.com/bzsanti/oxidizePdf/pull/820)).

Consumers should exercise their scanned PDFs and handle conversion errors;
this is not a claim of support for every PDF painting/compositing operation.
Core publication does not establish full Python/.NET parity (#710), outlined
Chinese text recognition (#583), or certificate-recipient encryption (#642).
The security-blocked encryption PR #658 is excluded.

## Generation performance

Standard font names no longer allocate a String per text operation. ASCII
character tracking uses a bounded initial reservation; non-ASCII inputs retain
the previous reservation policy. Unicode font serialization removes a redundant
font clone and shares parsed metrics between default and character widths.
PDF content compression settings and public API signatures are unchanged by
these performance changes
([#823](https://github.com/bzsanti/oxidizePdf/pull/823)).

The fixed corpus sample contained 83 inputs; 67 succeeded in both variants and
16 failed symmetrically in each mode. Across five paired blocks, the median
per-document time for registering/adding text plus first serialization fell
19.25% with Source Sans 3 and 25.05% with Source Han Sans SC. The comparison is
against develop commit 113ccb9, before #823, not directly against the published
5.5.2 package. These are results for added-text workloads on a size-stratified
sample, not a speedup guarantee for all PDFs. Median process peak RSS fell
2,124 KiB for the CJK workload; TTF RSS was effectively unchanged. Process RSS
includes import and other allocations and is not writer-only heap usage.

A separate full rewrite sweep covered all 6,128 unique contents from 9,051 PDF
paths under test-corpus/T0-T6: 5,827 paired successes and 301 paired errors, with
no asymmetric failures or timeouts. This route generally bypasses the new-font
optimization and did not establish a general rewrite speedup. The confirmed
CJK repeated-write regression in an intermediate candidate was corrected before
integration; the same fixed sample was rerun. Independent checks compared
streams, width arrays and page content for 224 output pairs. Text-position
comparison succeeded for 200 pairs; 24 produced invalid Poppler XML in both
variants, so their text positions were not validated.

Protocol, measurements and limitations:
[performance report](../reports/2026-10-26-issue-822-review.md).

## Development and validation

[#819](https://github.com/bzsanti/oxidizePdf/pull/819) partitions optimized CI
validation and caches compiled dependencies.
[#821](https://github.com/bzsanti/oxidizePdf/pull/821) adds official OmniDocBench
table/layout evaluation adapters and recorded results. It does not improve
recognition quality or add formula recognition.

All six post-merge workflows for develop d3f5ac5b passed, including corpus,
interoperability and text contracts. This evidence applies to the integrated
implementation. Release metadata, package verification and candidate CI are
tracked separately in #824. Publication additionally requires the release PR,
current-main validation and registry artifact identity verification.
