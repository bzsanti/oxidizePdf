# oxidize-pdf 5.6.0

This release adds opt-in text recovery and annotation appearance extraction,
fixes word spacing and classic cross-reference parsing, and repairs optional
PDF generation. Rust 1.88 remains the minimum supported version.

## Text extraction

- Infer ordinary spaces between separate text-show operations from available
  font metrics, including bounded simple-font width fallback (#869).
- Preserve tight TJ word gaps with a default threshold of 0.17 em instead of
  0.2 em; an explicit `tj_space_threshold: 0.2` retains the old sensitivity
  (#864). Preserve existing whitespace without duplicate inferred spaces (#859).
- Separate nearby form rows in layout/column extraction when text resets
  horizontally (#868).
- `with_visual_line_order(true)` orders horizontal single-column text by
  baseline and x position. Default extraction retains stream order. Hebrew
  and Arabic runs retain source order; this is not bidi conversion or general
  multi-column analysis (#868).
- `with_incomplete_tounicode_encoding_fallback(true)` uses supported explicit
  simple-font encodings and Differences for missing ToUnicode mappings.
  Existing mappings take precedence; strict decoding remains the default (#870).
- `with_annotation_appearance_extraction(true)` appends normal annotation
  appearances after page text in annotation order. Appearance resources and
  spacing state are isolated. Links, popups and Hidden annotations are skipped;
  NoView is included independently of Print. Invalid entries are ignored;
  decoding errors follow the selected strict/recovery API and resource limits
  remain enforced. Disabled by default (#861).

## Parsing and optional generation

Classic xref parsing handles CRLF split across buffer fills (#863).
`HighPerformanceDocument::save` writes actual PDFs and preserves existing files
on serialization/output failure. Ordered serial/Rayon callbacks retain page
content, images and registered fonts. Unsupported controls return errors;
no throughput improvement is claimed. Memory-pool retention respects its
configured capacity budget (#858).

## Compatibility and delivery

The new extraction behaviors are opt-in except the documented spacing/layout
corrections. Text output can change around word gaps and nearby form rows.
No new native product dependency is introduced. Existing 5.5.7 memory/time
tradeoffs remain documented in that release's notes.

Python and .NET adoption is tracked separately; publishing this Rust crate
alone does not update installed bridge packages or establish complete parity.
Release validation is recorded under core issue #872. CI and registry consumer
verification must complete before publication is accepted.
