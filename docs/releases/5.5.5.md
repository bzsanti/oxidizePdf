# oxidize-pdf 5.5.5

This patch release updates certificate dependencies and fixes extraction and
page-tree resolution. Public APIs and the Rust 1.88 minimum remain unchanged.

## Certificate dependencies

The minimum supported versions are rustls-webpki 0.103.16 and webpki-roots
1.0.10, addressing RUSTSEC-2026-0381 and RUSTSEC-2026-0382. The release lockfile
resolves webpki-roots 1.0.11. A certificate regression checks both a trusted
control and rejection of a distrusted public key under an explicit trust anchor.
No new advisory suppression is introduced. This is a targeted correction, not
a claim that every dependency is free of advisories.

## Parsing and text extraction

Strings inside encrypted object streams are no longer decrypted twice (#832).
Password validation and malformed ciphertext rejection remain in place.

Page-tree resolution retains nonzero object generations (#836), allowing
incremental signatures and document timestamps to resolve the original pages.
The regression checks that previously signed bytes remain intact.

Trailing TJ adjustments move the text cursor but do not themselves draw a
space. Extraction now waits to see whether another glyph consumes that position
before inferring a boundary (#833). This restores dates whose letters were
previously separated by artificial spaces and preserves real consumed gaps.

Compact indented rows can now receive a line boundary even when their baseline
separation is below the fixed newline threshold (#834). Tests distinguish these
rows from adjacent numbers, words and superscripts and cover transformed text.
This change concerns flat extraction; it does not claim to solve every layout
reconstruction case.

## Validation and bindings

The original JPMorgan and American Express pages were compared with rendered
pages and Poppler. Default and reading-order extraction retain the complete
dates and separate year headings from Total; the sequence of non-whitespace
characters is unchanged. These checks do not certify financial accuracy across
the full corpus. Upstream PDFs are not redistributed with this release.

The Python positional-chunks API also required its own page-font decoding fix
(oxidize-python #301, PR #302). That fix was validated with an explicit local core
consumer during development. Publishing this Rust crate does not publish a new
Python or .NET package; adoption by those bindings is tracked separately.
