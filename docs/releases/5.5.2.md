# Core 5.5.2

Release tracking: [#814](https://github.com/bzsanti/oxidizePdf/issues/814).
Baseline: published 5.5.1. Publication status is established by the matching
GitHub release and registry artifact, not by this preparation document.

This patch delivers #743, #744, #745, #795 and #797, plus the confirmed review
findings tracked in #812. Public signatures remain available and dependency
resolutions are unchanged. New `try_` APIs provide recoverable label errors.

## Migration

### Page labels

Alphabetic labels follow PDF repeated-letter numbering: A..Z, AA, BB..ZZ,
AAA, BBB, rather than spreadsheet numbering. Unicode prefixes are written as
BOM-prefixed UTF-16BE PDF text strings.

Formatting validates positive starting values and checked start-plus-offset
arithmetic. The default formatted-label budget is 64 KiB of UTF-8, including
the prefix. Legacy methods panic explicitly for invalid or oversized labels;
use `PageLabelStyle::try_format`, `PageLabel::try_format_label`,
`PageLabelTree::try_get_label` and `Document::try_get_page_label` for untrusted
inputs. Style/label `try_*_with_limit` methods accept an explicit byte budget.

Legacy all-label getters use a 16 MiB aggregate budget including String slots.
`PageLabelTree::try_get_all_labels` and `Document::try_get_all_page_labels`
accept an aggregate budget while retaining the default per-label limit.
They return an error without partial output when validation or a budget fails.

`PageLabelTree::from_dict` rejects malformed flat number trees, including
nonpositive St, invalid indices, incomplete pairs, duplicate or unsorted indices.
It returns `None` for the whole tree without an entry-specific diagnostic.
The writer propagates invalid-label errors rather than emitting St=0.

### Fonts, URI actions and annotations

Generic TrueType cmap formats 0/4/6 now reject missing/out-of-inventory glyphs,
as format12 already did. The parallel font parser also filters mappings against
maxp; missing/truncated maxp is an explicit mapping-extraction error. Explicit
subset requests reject glyph IDs outside maxp numGlyphs. Propagate these errors
rather than treating invalid fonts as validated coverage.

Mailto subjects are percent-encoded from UTF-8 bytes, with spaces as `%20`.
Recipient arguments are raw address data, not pre-encoded URIs: URI delimiters
are escaped; `@`, `+` and recipient-list commas remain literal. Mailbox syntax
is not validated. Query builders retain their existing form-style `+` spaces.

`PolygonBorderStyle`, `PolygonBorderStyleType` and `PolylineLineEndingStyle`
are publicly available for polygon/polyline configuration. They remain distinct
from the base annotation border and `LineAnnotation` ending types.
Width setters synchronize stroke width and bounding-box padding; the most recent
width or border-style setter determines their shared width. Direct public field
mutation remains possible: border width controls the serialized stroke, and
line width controls padding. Serialization rejects insufficient/nonfinite
vertices, invalid widths, dash patterns, colors, opacity or overflowing bounds.
Finite opacity setters retain clamping to 0..=1; NaN/Inf fail serialization.

### Batch operations

Rotate now performs actual rotation with page selection and composed angles.
It uses the existing reconstructive engine: it does not preserve signatures,
annotations, forms, original page boxes or all document-level structures.

Successful output is published atomically after serialization. Existing output
permissions are retained; new output inherits input permissions. Only ordinary
mode bits are copied on Unix, excluding setuid/setgid/sticky. Other platforms
copy `std::fs::Permissions`, such as the Windows read-only attribute; a refused
replacement reports failure. Existing symlinks retain the link and update their
target; dangling links fail unchanged. The destination parent must be writable.
Atomic replacement does not preserve hardlinks, ownership, ACLs or extended
attributes and is not isolation against concurrent path replacement.

Positive timeouts remain completion-checked: a job can report timeout after a
complete output was published. They do not cancel or roll back the operation.
`BatchJob::Compress` is unsupported for every quality value and fails explicitly
without creating or overwriting output; it no longer returns success for a copy.

## Validation and adoption

The changes have independent quality-rust reviews, both Kripteia analyses,
regression/mutation evidence, independent PDF/TTF checks and multiplatform CI.
Release publication additionally requires the exact candidate's optimized tests,
T2/T3 differential gates, interoperability and complete current-main validation.
No expanded ISO compliance or full structural-rotation guarantee is claimed.

After publication, downstream consumers should pin 5.5.2, record its registry
checksum and run their label/font/URI/annotation/batch acceptance suites. Core
publication does not establish full Python/.NET parity (#710), OCR #708 or
recipient encryption #642. The security-blocked PR #658 is not included.
