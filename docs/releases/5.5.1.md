# Core 5.5.1

Release tracking: [#800](https://github.com/bzsanti/oxidizePdf/issues/800).
Baseline: published 5.5.0. Publication status is established by the matching
GitHub release and registry artifact, not by this preparation document.

This patch corrects redaction, layout and form-policy contracts without removing
public signatures or changing dependency resolutions. `LayoutManager::try_new`
is an additive way to report unsupported geometry; the existing constructor
remains available.

## Migration

- Irreversible redaction now rejects retained font fields outside its audited
  Standard-14 Type1 contract, including descriptors, ToUnicode and private fields.
  Such inputs return an error without successful output. This does not claim
  arbitrary-PDF forensic erasure or change visual masking.
- Layout reservations return the element's top Y in local coordinates, before
  advancing the cursor. For a 200-point page with 10-point margins, reserving
  height 40 with spacing 10 returns 190 in PdfStandard, not the previous erroneous
  180. Consumers must convert ScreenSpace/Custom positions and sizes when passing
  them to APIs expecting PDF coordinates. Axis-aligned Custom transforms consume
  finite capacity; shear/rotation coupling both axes is unsupported.
- Form filling now enforces DocMDP and FieldMDP, including aliases of the same
  object. Propagate permission and malformed-policy errors; do not replace them
  with success or duplicate the policy parser in bindings. Allowed P=2/P=3
  updates retain incremental prefix preservation and ReadOnly checks.

## Validation and adoption

The release includes the CI provenance and package-identity gates from #790.
veraPDF 1.30.3 creates configuration on first launch; CI initializes it before
parallel validation. Actual qpdf/PDF-A checks and their negative controls remain
required. Unavailable or failed validators are not accepted as passing.

After publication, Python and .NET consumers should pin 5.5.1, record its registry
checksum and run their redaction, layout and form-policy acceptance suites
(Python #263/#244 and .NET #92). Core publication alone does not close full bridge
parity #710. OCR #708 and certificate recipient encryption #642 remain separate;
the security-blocked recipient-encryption candidate is not included.
