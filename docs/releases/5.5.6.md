# oxidize-pdf 5.5.6

This patch release fixes signed-field permission enforcement and semantic chunk
budgets. Public API signatures, dependencies and the Rust 1.88 minimum are unchanged.

## Signed-field permissions

Incremental signing now enforces Lock/P restrictions recorded in signed fields,
including inherited and indirect definitions. A later revision cannot relax an
earlier signed restriction. Shared field aliases are distinguished from cycles.
Malformed policies are rejected instead of silently granting permission (#843).

Signing operations previously accepted despite a signed restriction can now fail.
Dedicated document timestamps retain their narrowly scoped handling; this does
not grant ordinary signing operations an exemption from signed-field permissions.

## Semantic chunk budgets

The semantic chunker measures joins using the selected counter, including the
optional cl100k_base tokenizer. Overlap is retained only when it fits both the
overlap budget and the next chunk budget; it can be omitted when it does not fit.
The oversized flag is calculated from the final emitted text (#847).

Indivisible sentences and preserved structures can still exceed the requested
limit and are marked oversized. This release does not promise that every chunk
fits a hard maximum. Chunk boundaries and overlap may change for the same input.
The default word-proxy counter and optional tiktoken feature remain available.

## Documentation and bindings

The Rust Docs7 site and Context7 configuration provide introductory guides and a
quickstart (#845), not a complete API reference. Index refresh is subject to the
provider cooldown and is separate from publishing the crate.

Python 0.23.3 and .NET 0.20.2 currently use core 5.5.5. Publishing this Rust release
does not update those packages or complete bridge parity (#710). Adoption of the
corrected core and the .NET exact-token-counter work (#104) are separate deliveries.
