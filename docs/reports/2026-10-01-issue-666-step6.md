# #666 — contratos de escritura vertical

Issue: #666 — test(text): build normative encoding and glyph-spacing contract batteries — https://github.com/bzsanti/oxidizePdf/issues/666

Estado parcial, RED. Se incorporan nueve tests Rust y once escenarios sin cambios
de producción. La issue sigue abierta y fue confirmada antes de activar el bloque.

## Contratos implementados

Identity-V y CMap incrustado WMode 1 con CIDFontType2/TrueType real; avance por
defecto, DW2 explícito, W2 en forma array/rango y fallback para CID sin entrada;
ajustes TJ positivos/negativos, escala horizontal Tz 50/200 y espaciado Tc.
El fixture reutiliza la fuente completa fijada, CIDs 17/19, GIDs 2/3 y ToUnicode A/B.
No se atribuye conformidad tipográfica CJK a las letras latinas de control.

Norma: ISO 32000-1 §9.7.4.3 y §9.4.4. Con fontsize 10 y pen inicial (100,700):

| Perfil | Pen esperado de B |
| --- | --- |
| Default DW2 [880 -1000] | (100,690) |
| DW2 [900 -1300] | (100,687) |
| W2 de A con w1y=-1200 | (100,688) |
| TJ +300 después de A | (100,687) |
| TJ -300 después de A | (100,693) |
| Tc=2 | (100,692) |
| Tz=50 o 200 | (100,690) |

El fallback A/B/A comprueba además el tercer pen (100,675). Las aserciones
acumulan los fallos para ejecutar ambos signos/escalas y todos los glifos;
no se corta la matriz al primer fallo. Los cambios Tr separan fragments sin
mover el pen. El último A usa Tr=0 para evitar duplicar trazas fill+stroke.

## Validación externa integrada

Los once PDFs se añaden al manifest: 25 casos totales. MuPDF coincide en texto
en los 25; Poppler en 17, con las ocho limitaciones históricas separadas; qpdf
valida los 25. En los once verticales ambos lectores coinciden en las líneas
A/B o A/B/A; no se eliminan saltos de línea para obtener el resultado.

Se añade geometría opcional al validador. Nueve casos comparan los orígenes de
glifo devueltos por MuPDF get_texttrace con valores independientes. Para escala
horizontal unitaria y página de altura 792:

    origin0 = (pen_x - vx * fontsize / 1000,
               792 - pen_y + vy * fontsize / 1000)

Ejemplo default: A=(97.28,100.8), B=(97.06,110.8) en coordenadas MuPDF con y hacia
abajo. Los tests Rust comprueban el pen, no ese origen0. `rawdict` proporciona
orígenes de layout distintos en vertical y no se usa como sustituto de la traza
de colocación. La tolerancia declarada es 0.001 punto. Las coordenadas esperadas
se fijaron desde métricas/ecuaciones, no desde los resultados del lector.

Los dos casos Tz comparan texto externamente y pen en Rust, sin declarar
validación externa de offsets escalados de glifo. No se ha generalizado la
conversión a rotación/cizallamiento. La geometría ausente se registra como no
comprobada, no como PASS. Un texto correcto con origen incorrecto falla.

Diez pruebas del validador Python pasan, incluidas dos nuevas: mutar una posición
manteniendo texto correcto y rechazar una expectativa geométrica vacía. No se
suman como contratos PDF del producto. No hay nuevas omisiones ni excepciones
Poppler para hacer pasar este bloque.

Evidencia: [logs, PDFs, validador y hashes](2026-10-01-issue-666-step6-evidence/).
Manifest y README describen explícitamente líneas internas y el contrato de
coordenadas. No se ha ejecutado una revisión Kripteia nueva, CI o corpus completo.
