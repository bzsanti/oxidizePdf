# Review #734 — grammar-aware inline image extraction

Issue: #734 — fix(images): parse inline image dimensions and return correctly encoded data — https://github.com/bzsanti/oxidizePdf/issues/734

Inline extraction now uses ContentParser's strict grammar. It preserves declared dimensions, skips BI/ID/EI-like names, comments and strings, and uses the grammar's known sample length to preserve binary EI-like bytes and whitespace-valued pixels. Known raw/Flate/ASCII transport samples use the existing PNG encoder; unsupported filters, missing color metadata, Decode/ImageMask and opaque DCT payloads are explicitly Raw. A PDF filter name alone no longer serves as proof of a JPEG file. No new dependency or public signature.

## Requirements and evidence

Original public RED: six failures, including 4×100 instead of 4×2, false inline images from text and arbitrary bytes labeled PNG. Eleven final public contracts cover the original example, one-line and full/multiline keys, CRLF, literal whitespace/NUL/EI pixels, Flate and ASCIIHex, missing/negative dimensions, unknown filter Raw, malformed compressed input, missing metadata/empty content controls, absent EI and opaque DCT. PNG output is independently decoded and compared against literal bytes and geometry. Positive and negative expectations were retained throughout.

Final integration: eleven new contracts plus 28 image regressions PASS, including packed grayscale, CMYK/alpha, Indexed/qpdf and in-memory/file parity. Units: 54 extraction and 96 content-parser PASS. Strict all-target Clippy with external-images passes on the final sources; the command result is recorded alongside this report.

## Findings resolved

- Strict parsing still recovered an image lacking EI. Public RED reproduced successful extraction; strict_inline_end now rejects that case only for parse_strict. A positive control confirms general best-effort parsing remains available. Parser unit regression passes.
- Delegating DCT directly to the XObject path would label arbitrary payload JPEG based only on the filter declaration. Public RED reproduced that; inline DCT and chains containing it are retained explicitly Raw.
- Removed obsolete private substring/dimension and magic-byte helpers and their nine implementation-specific tests. Those tests included invented 100×100 dimensions and unknown-data-as-PNG expectations. Their relevant behavior is replaced by stronger public extraction/independent-decoder contracts, including full-name and multiline controls. This is intentional correction of the defective contract, not weakening assertions to obtain green tests.

Manual review traced tokenizer delimiter handling, bounded inline parameter nesting, conversion of supported object types, sample preparation, limits and output accounting. Dimensions must be positive representable u32 values; pixel and image-count limits run before conversion, byte limits account for output. Unknown parameter shapes return errors. Existing PNG/stream limits are reused; no new global content-memory bound is claimed. Strict parsing may explicitly reject unsupported/malformed content rather than silently extracting from it.

Filtered stream boundaries still use the shared grammar's EI rules; this change does not claim a new universal decoder for every filter or corrupted content recovery. Unsupported results are not advertised as decoded pictures. ICC/color-management and the separately recorded 16-bit extraction stride limitation are outside this correction.

## Calidad de Tests (Kripteia)

Required analyses ran on both product files, retained extraction unit tests and new public tests. Final integration score 91/100 (eleven); product extractor 90/100 (29 retained tests), parser 89/100 (96), separate unit file 95/100 (25). Scanner claims that helper-based tests make no production call are false positives: the helper invokes public PdfReader and ImageExtractor, then the independent image decoder. Literal expected samples distinguish geometry, delimiters, color payload and format. Initial RED and both QR RED counterexamples are retained.

## Análisis de Seguridad (Kripteia Security)

All four scans report no security issues. Manual review covers depth bound inherited from content grammar, checked dimensions/budgets, no delimiter search through text, errors for invalid parameter types, and no inference of image-file validity from arbitrary bytes. No new unsafe code, network access or production subprocess. Scanner results do not replace those checks or establish whole-parser safety.

No unresolved finding in this correction. Final remote CI and merge are separate acceptance gates. Publication targets develop and follows the preceding reviewed image corrections.
