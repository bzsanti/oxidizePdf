## Resumen ejecutivo

QR individual #758 sobre develop 239b71f2, rama fix/issue-758-effective-options.
Se conectan eager y buffer a PdfReader, se preservan sus opciones/caches, se
expone configuración solicitada/efectiva de ambos adaptadores y se corrige la
contabilidad de retención. LazyDocument declara mapping y streaming de contenido
como capacidades no soportadas: resultado tipado permitido por la issue, no una
implementación de esas capacidades. Inventario completo en docs/MEMORY_OPTIONS.md.
La publicación y adopción por Python/.NET siguen siendo pasos separados.

Entrada de contratos: tests/issue_758_effective_options_test.rs. Fixtures PDF/xref
se construyen con sintaxis independiente; compresión usa encoder zlib y límite
se deriva de bytes conocidos antes de comprimir. ObservedReader solo registra
I/O; no sustituye parser ni políticas. Pares de opciones hacen fallar el test si
se ignoran buffer/eager/cache/content budgets. RED histórico de dos defectos en
evidence; todas las aserciones van contra API pública. Las regresiones #724/#725
siguen vigentes (19+12 PASS). No se reimplementa el streaming real ya integrado.

El primer montaje I/O comparaba buffers1/4096: ambos eran menores que la lectura
directa del parser y daban3/3 llamadas. Esto es comportamiento válido de BufReader,
no un defecto. Se corrigió a1/65536; docs explican que buffer_size no es un máximo
de lectura. La selección discrimina la configuración efectiva sin copiar su lógica.

Fuera de las garantías: límite global de proceso/RSS, interrupción, red no seekable,
rendering progresivo, mapeo de archivos mutables y streaming de payloads dentro de
LazyDocument. Mapping y streaming no soportados siguen pendientes bajo #710;
no se activa unsafe nuevo ni se declara MemoryMappedFile auditado/certificado.
La política permitida por #758 es informar explícitamente estas capacidades,
preservando presets y sin presentar valores almacenados como activos.

## Hallazgos

1. **Opciones almacenadas sin efecto observable**: `oxidize-pdf-core/src/memory/lazy_loader.rs:58` — lazy_loading y buffer_size no alteraban carga/I/O. Corregido: recarga del buffer conservando posición/caches y precarga de referencias activas cuando lazy=false; fallos propagados. Mapping/streaming quedan como unsupported tipado. Contratos RED/GREEN y controles I/O verifican el cambio.
2. **Estadística de caché no reflejaba retención**: `oxidize-pdf-core/src/memory/mod.rs:226` — cached_objects permanecía cero. Corregido leyendo el tamaño del LRU; prueba de inserción/evicción/clear demuestra la población exacta. Contadores no se anuncian como mediciones globales de memoria.
3. **Capacidad de caché causaba reserva anticipada arbitraria**: `oxidize-pdf-core/src/memory/cache.rs:20` — with_capacity(capacity) reservaba antes de insertar, y una capacidad MAX podía provocar panic de capacidad. Corregido mediante contenedores inicialmente vacíos que crecen según inserciones, manteniendo límite lógico. Control de capacidadMAX con PDF real pasa; hallazgo original de reserva se deriva de fuente, no se afirma medición de peak memory ni reproducción previa de abort por OOM.
4. **Documentación describía requests como modos activos**: `oxidize-pdf-core/src/memory/mod.rs:116` campos/builders/ejemplo — habilitar mapping/streaming parecía soporte funcional de LazyDocument. Corregidos docs y ejemplo; inventario enumera consumidores, unidades, presets y estados. Ambos adaptadores exponen configuración efectiva sin eliminar valores solicitados. No se atribuye una versión publicada aún inexistente.

## Análisis de Seguridad (Kripteia Security)

Las cuatro ejecuciones reportan `No security issues found.` Inspección manual:
no unsafe nuevo, no dependencias nuevas, IDs vienen del índice activo, eager usa
el parser existente y conserva límites/syntax policy, errores de seek/parse se
propagan. Buffer >isize::MAX se rechaza antes de su asignación; esto no garantiza
que cualquier tamaño menor sea asequible ni establece un cap de proceso. Cache
lógica no preasigna MAX. La retención se decide después de materializar la página,
con alcance explícito; no se confunde ese presupuesto con prevención de toda
asignación. Snapshot de configuración no permite mutar el documento activo.
