# Revisión #642 — cifrado de destinatarios

## Resumen ejecutivo

Implementación candidata sobre `develop` c4e08c7 + documentación #641 a6240e0.
El PR #657 de documentación ya está integrado (48d8b8f); #642 no se declara
resuelta ni soportada. Revisión funcional completada; aceptación de seguridad
bloqueada por un hallazgo de dependencia. Huellas del código y evidencia real:
[archivo](2026-09-29-issue-642-evidence/).

La API nueva conecta Document → CMS de destinatarios → AESV3 → PdfReader.
El shell `PublicKeySecurityHandler` permanece explícitamente no soportado.
Perfil acotado: Adobe.PubSec/adbe.pkcs7.s5, RSA-OAEP SHA-256/MGF1 SHA-256,
CMS y contenido AES-256-CBC, metadata cifrada, permisos por destinatario,
xref clásico al escribir y xref/object streams al leer. CBC no autentica
integridad. No PAdES, PKI gestionada, claves EC ni RSA v1.5 de transporte.

Los fixtures fijan valores semánticos, no ciphertext generado por la librería.
Las claves versionadas son exclusivamente datos públicos de prueba. El oracle
Python/OpenSSL no forma parte del grafo del producto. Límites de tamaño DER y
número de destinatarios fueron inspeccionados; no se presenta esta revisión como
fuzzing exhaustivo, auditoría criptográfica ni medición de tiempo constante.

## Hallazgos

1. **Aviso RSA sin resolver:** `oxidize-pdf-core/src/encryption/recipient.rs:383` invoca
   una operación privada de `rsa 0.9.10`. [RUSTSEC-2023-0071](https://rustsec.org/advisories/RUSTSEC-2023-0071.html)
   sigue sin versión corregida; upstream mantiene [RSA#626](https://github.com/RustCrypto/RSA/issues/626)
   abierto. No se ha demostrado explotación de esta configuración, pero tampoco
   exención por usar OAEP y blinding. Corrección necesaria: proveedor puro Rust
   adecuado o análisis independiente concluyente de este camino exacto. PR en
   borrador, issue abierta y documentación sin declaración de soporte.
2. **Reconstrucción de catálogo ignoraba el bloqueo en el prototipo:**
   `oxidize-pdf-core/src/parser/reader.rs:604`. Los primeros tests obtuvieron
   catálogo pese a estar bloqueado. Corregido: el nuevo perfil exige unlock y
   usa la resolución normal, sin reconstrucción alternativa. El guard público
   falla en el prototipo y pasa en el candidato final.
3. **Filtro Crypt implícito incorrecto en imágenes del prototipo:**
   `oxidize-pdf-core/src/encryption/object_encryption.rs:221`. La reutilización
   inicial del cifrador legacy insertaba `/Crypt` sin parámetros adecuados en
   streams sin filtro. Corregido mediante modo interno de filtro implícito para
   destinatarios; cifra también strings del diccionario y no excluye nombres
   ordinarios como ID. Imagen exacta verificada por ambos lectores.
4. **Descifrado doble de strings de object streams:**
   `oxidize-pdf-core/src/parser/reader.rs:1148`. El camino previo aplicaba el
   cifrado de objeto después de descifrar el stream contenedor. El perfil nuevo
   toma directamente el objeto ya descifrado. Mutación que restaura el segundo
   descifrado falla contra el fixture pyHanko.
