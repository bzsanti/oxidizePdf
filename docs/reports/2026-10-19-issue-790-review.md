## Hallazgos

1. **Toolchain alias is not an effective input**: `scripts/ci_evidence.py` initially
   included RUSTUP_TOOLCHAIN, which can differ for identical resolved compilers.
   Removed the alias; rustc -Vv and Cargo remain mandatory. This prevents an
   unnecessary optimized test repetition across CI and tag action entry points.
2. **API outage test missed the API boundary**: the first probe test injected the
   error in fingerprint creation. Changed it to inject a transport failure through
   GitHub.get while executing real receipt preparation and output handling.
3. **Version existence must be exact**: old release logic compared max_version and
   could treat a registry error as absence. Replaced it with exact-version status
   handling, tag/manifest validation and post-publication checksum comparison.
4. **Coverage provenance and duplication**: the old workflow_run chain could start
   another suite after repeated CI. Coverage now belongs to the same CI run and
   uses its actual checkout and short-lived job receipt; optional status preserved.

These findings were corrected within #790. No known local acceptance blocker
remains; remote validation is still required. The historical main run failed in
SPI+semantic while the old release gate passed. Its Rust failure is not repaired
or claimed resolved by this CI change; the new gate explicitly rejects failure.
No unrelated product correction is included.
