## Hallazgos

1. **Panic con FontFile2 truncado**: `oxidize-pdf-core/src/text/extraction_cmap.rs:664` invoca un parser cuya indexación en `src/text/fonts/truetype.rs:229` no comprueba que exista el directorio. `.ok()` no captura panic. La entrada mínima `00 01 00 00 00 01 00 00 00 00 00 00` interrumpe `extract_from_page` cuando se activa la opción. También ocurre con ToUnicode utilizable porque se analiza el programa antes de aplicar esa precedencia. El defecto del parser preexiste, pero este PR lo expone por una nueva ruta de extracción. Corrección: validar tamaño del directorio y rangos antes de indexar, devolver ParseError y evitar analizar el programa si ToUnicode hace innecesario el fallback. Añadir regresiones de extracción con/sin ToUnicode y revisar límites/arithmetic de los cmap que ahora se procesan.
2. **La caché ignora cambios de configuración**: `oxidize-pdf-core/src/text/extraction.rs:873` cambia el booleano sin invalidar `font_object_cache`; `:3558` devuelve FontInfo derivado de la opción anterior. Reproducido en ambos sentidos: false→true conserva �� en vez de AB; true→false conserva AB en vez de ��. Corrección: si cambia el valor, vaciar las cachés derivadas o incluir la política en su clave. Añadir una regresión con el mismo extractor/documento, contrastada con extractores nuevos.
3. **Se admiten GID que no existen**: `oxidize-pdf-core/src/text/extraction_cmap.rs:684` acepta cualquier GID no nulo que haya almacenado parse_cmap; sus formatos 0/4/6 no verifican numGlyphs. Con el fixture simbólico y maxp.numGlyphs=1, el programa solo declara GID 0, pero se extrae AB de referencias a otros GID. Esto fabrica texto a partir de un programa inválido aunque la API promete resolver primero un glifo. Corrección: exigir `gid != 0 && gid < program.num_glyphs` antes de usar nombres o fallback de byte, conservando la búsqueda alternativa pertinente y U+FFFD cuando no haya selección válida. Probar GID 0, último válido y primer inválido.
