# Issue 858: actual optional PDF generation

Issue: https://github.com/bzsanti/oxidizePdf/issues/858 (OPEN).
Base: develop b0e7758c44995d825f9135cce16fc932f4eecc08.

The published 5.5.7 performance save path returns success without creating a
file. Two registry consumer contracts reproduce that failure. This change
writes through the canonical Document/PdfWriter, preserving content and resources,
and publishes a same-directory temporary file only after serialization and flush.
Existing destination permissions are retained; symlinks resolve to their target.

Owned pages can be appended directly or built through ordered callbacks. Rayon
bounds callback concurrency; explicitly sequential generation creates no worker
pool. Failed callbacks append no partial result. Callback side effects cannot be
rolled back. Unsupported controls fail before callbacks execute. Descriptor-only
pages remain blank; unresolved content references are rejected.

The memory budget bounds retained pool capacity, not live pages, callback
allocations or process RSS. Buffered output retains the full PDF; direct output
avoids that buffer but retains source pages. Legacy metadata estimates remain
estimates. There is no throughput claim or version bump in this change.

- Final integration contracts: 11 PASS with performance and 11 PASS with
  performance,rayon. Tests cover actual content, images, embedded fonts, ordering,
  concurrency, atomic callback failure, output failure, repeated save and budget.
- Independent consumer: four PDFs pass qpdf; Poppler confirms ordered text and
  rendered red/white pixels at expected coordinates in both output/execution modes.
- Full library baseline during implementation: 6,817 PASS, three existing ignored.
  Final focused library and documentation runs remain pending at commit preparation.
- Rust 1.88 library check, Clippy for both feature configurations, formatting,
  diff checks and 21 CI gate contracts pass.
- Independent correctness/security and maintainability reviews completed by
  core858_correctness and core858_quality; no remaining findings. Corrections
  cover sequential pool creation, success-only coherent statistics, image oracles,
  validator dependency direction and preservation on serialization failure.
- Kripteia: test score 98/100, 77 tests across eight source/test files; security
  scan reports no issues. Automated scores supplement behavioral evidence.

The canonical writer remains responsible for PDF encoding and resource handling;
the generator handles scheduling and ordered collection. The shared page validator
lives in the parent module. No second encoding engine or .NET scheduler is added.
Existing batch and Rotate behavior is outside this change.

CI now tests both feature configurations on Linux, Windows and macOS, and the
required-job policy includes all six names. Remote CI remains pending until the
branch workflow finishes. Durable execution logs are maintained in the session
tracking checkout under docs/reports/2026-11-06-core-858-evidence.

Integration/release and .NET adoption remain separate pending steps. No automatic
PR is created under the parity workflow; .NET must consume a published validated
core before exposing optional generation.
