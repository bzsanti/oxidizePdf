Initial base execution: seven intended failures, one unchanged-batch control passes. Failure output shows lost title, lost ParentTree entry, wrong parent, stale child index and plan accepting a later invalid index. qpdf independently reads `/T (changed)` instead of `/T (title)`. Logs preserved. Subsequent eight tests pass after the fix. Final eleven contracts extend this evidence, rather than replacing the RED input expectations.

The first permission fixture had a synthetic ByteRange that did not cover the certification object's offset. That test failed before reaching the intended permission guard. It was corrected to compute covered ranges while preserving serialized offsets; this is fixture repair, not a change to authorization or a product defect. The initial failed contract log remains available.

Planning holds an in-memory dictionary overlay and current parent/index state, uses the same child manipulation helpers as application, and only omits mutations that are no-ops at their position. Returning to the original value writes a revision; the documented inventory describes written objects, not a net semantic diff. Existing element identity/cycle checks, policy_reader, preparation restrictions and serialization remain in place. Allocation order for new elements and xref-stream identity is unchanged. Memory is proportional to touched dictionaries plus the existing parent index; no global memory bound is claimed.

Review traced public exports, both plan/apply callers, validation/preparation, dictionary replacements and parent graph, IncrementalUpdate allocation/replacement/finish, validation reports and DocMDP enforcement. No new dependency, unsafe code, filesystem write in the editor, or public API type was introduced. No-op decisions now also reflect earlier MCID associations, without treating an invalid ordinary-editor validation report as success of structural validation. The prepared editor still requires a valid final document.
