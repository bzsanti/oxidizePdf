Issue: #763 — fix(pdfa): preserve XMP properties and validate/escape XML in metadata round trips — https://github.com/bzsanti/oxidizePdf/issues/763

Scope: public pdfa::XmpMetadata reader/serializer and XmpPdfAIdentifier textual serialization, based on reviewed #741 implementation 1f87b1ab. ## Hallazgos

No additional confirmed findings in the manual architecture/contract and line-level review. The five reproduced issue defects are corrected. Tests derive literal expectations rather than reuse production decoding; the independent XML reader checks output separately from the library parser. Production flow was traced from public parse/to_xml through namespace selection, RDF container values and PDF/A validator consumption. Helper bounds and dependency graph are unchanged from #741.

Supported-profile limits are explicit: scalar PDF Keywords is one entry and retains historical precedence over dc:subject; arbitrary RDF resources/graphs are not silently interpreted. to_xml retains its existing infallible String signature and requires XML 1.0 text: NUL and other forbidden characters are not silently removed and parse returns a typed error. This is tested and documented; no claim that arbitrary Rust strings are valid XML is made. The issue's XML-representable Unicode and markup-injection contracts are demonstrated.
