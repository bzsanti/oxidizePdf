## Resumen ejecutivo

Base develop aac17faa2e967a14d8252e2ca2c9515761be16ae; Rust 2021/MSRV 1.88.
Alcance: constructores públicos Image::from_rgba_data/from_gray_data y sus
consumidores RGB, alpha, soft mask, escritura/transparencia y roundtrip.
Se preservan firmas, variante InvalidImage y valores de muestras válidas.
No se añaden dependencias ni se modifica from_raw_data, el decoder PNG (#736)
o las políticas de extracción de imágenes (#732–#734).

Un helper privado rechaza dimensiones cero y comprueba píxeles/componentes en
u64, conversión a usize y límite isize::MAX de Vec<u8>. Se compara el tamaño con
el buffer del llamador antes de reservar salida. RGB usa tamaño comprobado y
alpha deriva del tamaño RGBA validado dividido entre cuatro. No se impone un
límite arbitrario de resolución: una imagen grande representable con datos
completos conserva su contrato. Esto no promete recuperar agotamiento general
de memoria con entradas válidas enormes.

## Contratos y evidencia

Fuente: criterios #735 confirmada OPEN, muestras pequeñas literales y ausencia
de desbordamiento/truncamiento antes de validar o reservar datos. Los probes usan
la API real y no el helper como sustituto.

RED debug: cuatro fallos previstos y tres controles PASS. RED release: tres fallos
por Ok inválido y tres controles PASS. En el RED release se excluyó temporalmente
el caso exacto 65536×16384: la implementación antigua habría reservado alrededor
de 4 GiB. Se ejecutaron en su lugar productos cuyos píxeles/capacidades envuelven
a cero, sin reservas grandes. Una vez corregido, se retiró esa exclusión: el test
final no contiene ignore ni cfg que omita el caso en release. No se cambiaron
expectativas para acomodarlas al producto. Release usa el perfil real del repo
(opt-level=3, LTO), sin forzar overflow-checks para esconder el defecto.

Los errores de RED son fallos conductuales, no de compilación/montaje. Retirar el
helper y restaurar los productos u32 reproduce esos fallos. No se ejecutó una
mutación adicional: RED/GREEN ya demuestra discriminación. Los arrays RGB/alpha
y grises esperados son literales independientes; no se recalculan con producto.

Trazado manual: la validación positiva asegura múltiplo de cuatro antes de chunks
RGBA, por lo que los índices [0..3] son accesibles; tamaños de RGB/alpha no pueden
exceder el RGBA ya aportado. Alpha y soft mask conservan dimensión, ocho bits y
muestras exactas. Gray no reserva salida adicional. Conversión checked a usize
cubre plataformas más estrechas; ejecución local es x86_64, no se afirma prueba
runtime 32-bit. Los errores no incluyen datos del buffer del usuario.
