## Resumen ejecutivo

Revisión de #724 sobre develop `7a6d0723c7fd8f90d527780a7801a9af865c3e09`, incluyendo el diff local. Los cuatro lectores dejan de fabricar páginas, texto y objetos Null. PageStreamer, StreamingDocument y StreamProcessor usan el lector PDF existente; IncrementalParser delimita bytes y delega los valores al lexer/parser de objetos. La revisión manual cubre contratos, consumidores, pruebas, límites, errores y concurrencia. Implementación y revisión local completas; publicación/CI pendientes. #719 conserva su alcance de auditoría.

Las páginas materializan contenido y texto; la caché mide payload retenido, no RSS ni toda la memoria del lector. La API incremental emite registros sintácticos, no acredita validez documental: exige Length directo, limita registros a 16 MiB y profundidad a 128, y rechaza explícitamente longitudes indirectas, ObjStm/XRef, cifrado y revisiones incrementales. Esos documentos deben procesarse con PdfReader. `finish()` valida el EOF físico; el helper lo llama automáticamente. Los eventos de un objeto se entregan después de analizarlo por completo.

## Hallazgos

1. **Páginas y texto independientes de la entrada, corregido**: `streaming/page_streamer.rs:147`, `streaming/mod.rs:147`, `memory/stream_processor.rs:54` — las rutas originales devolvían tres/diez páginas y texto literal. Ahora navegan páginas reales, conservan MediaBox completo y entregan contenido/texto fuente. Los fixtures de integración basados en un mero header se sustituyeron por PDFs válidos; se retiraron expectativas de placeholders. La menor cantidad de tests no es una mejora de métricas ni un nuevo baseline de calidad.
2. **Parser por líneas con objetos Null y corrupción de bytes, corregido**: `streaming/incremental_parser.rs:134` — delimitación byte a byte con estado persistente de strings, comentarios, hex y payload de longitud conocida; lexer compartido para valores reales. No se usa UTF8 lossy. Se comprueban generaciones, límites, xref/trailer y EOF físico.
3. **Streams anidados podrían eludir la comprobación de Length, corregido durante revisión**: `streaming/incremental_parser.rs:224` — el marcador stream se rechaza dentro de un objeto compuesto o trailer antes de invocar el parser recursivo. El control con Length máximo confirma error y ausencia de ObjectEnd; no se ejecutó una mutación que pudiera provocar una reserva desmesurada.
4. **Comentarios entre valor y endobj, corregido durante revisión**: `streaming/incremental_parser.rs:360` — lectura de token significativa, en vez de exigir que el siguiente token sea endobj sin comentario intermedio. RED ejecutado: 16 PASS/1 FAIL por Missing endobj; GREEN posterior.
5. **Compatibilidad de errores, identidad y auto traits, corregido durante revisión**: `streaming/page_streamer.rs:93`, `memory/stream_processor.rs:92` — conservar InvalidHeader y el índice real al reanudar; preservar Sync y RefUnwindSafe. Se revisó el único unsafe impl nuevo: el documento interior es privado, todos sus accesos requieren `&mut self`, no escapan referencias a sus RefCells y el único método compartido lee Option<u32>. No se añade unsafe Send ni acceso compartido a estado mutable. La alternativa con Mutex exigía Send adicionalmente y fallaba para un lector Sync no Send; se conserva el límite original R: Sync. Las futuras adiciones de métodos deben respetar esta invariante explícita.
6. **Límite posterior a read_to_end, preexistente y fuera de esta corrección**: `memory/stream_processor.rs:186` — ContentStreamProcessor, diferente del adaptador de páginas corregido, lee todo antes de comprobar max_stream_size. Solución propuesta: lectura limitada a máximo+1 y prueba instrumentada de bytes consumidos. Bloqueado sin issue específica aplicable; mantenimiento/bzsanti debe crear/vincular una OPEN. No afecta la eliminación de páginas/objetos inventados, pero no se afirma que esta API imponga un presupuesto estricto de memoria.
7. **Test de contenido inválido sin oráculo, preexistente**: `memory/stream_processor.rs:514` — acepta indistintamente éxito/error. Sustituir por contratos independientes de entradas válidas e inválidas bajo una issue específica. Misma dependencia externa y responsable; no se corrige ni se recalibran métricas aquí. Las pruebas de LazyDocument que retornan temprano conservan el seguimiento #725; ChunkProcessor y TextStreamer mantienen #726/#739.
