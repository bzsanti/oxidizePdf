20,466 to 9,483 bytes, and allocation/reallocation calls from 4,816 to 3,484
per document. This is implemented product work, not another profiling-only
milestone. Local validation and review pass; CI/integration remain pending at this snapshot.

memory APIs, preserving size/time upper bounds. Both changed test targets pass
12/12 on the final sources; unchanged workspace results are reused. No historical stats changed. Archived text logs omit trailing blank lines; full
original command output remains in the local target directory. The isolated checkout has no external corpus PDFs;
workspace success must not be reported as a new T0–T6/OmniDocBench corpus run.
Parser/extraction code and corpus baselines are unchanged; writer outputs are
validated directly by the focused and independent checks below.

## Measurements and reproduction

See adjacent `2026-10-07-issue-661-evidence/`: `probe.rs`, Cargo.toml/lock,
`compare.py`, `samples.jsonl`, `summary.json`, `paired-uncertainty.json`,
`allocations.json`, `validation.json`, `raster-comparison.json`, `identity.json`
and `environment.json`. The release package checksum/source identity is in

This is a new controlled experiment, not a replacement of oxidize-stats or the
2026-09-29 series. Build an independent consumer from the included manifest,
lock and `probe.rs` as `src/main.rs`; adjust only the oxidize-pdf path to the
exact control/candidate checkout. Run `cargo build --release --locked --offline`
then preserve `target/release/writer-perf-probe` as `control-timing` or
`shared-timing`. Build again with `--features alloc-count` and preserve the
corresponding `*-alloc` binary. Place these four binaries next to `compare.py`
and run it with an absent `results/` directory. Its explicit refusal to reuse
that directory prevents accidental mixing of samples.

Both variants use Rust1.96.0, consumer release opt-level3/debug1, no workspace
LTO override, compression-only product features, and the same lock with
flate2 1.1.10/miniz_oxide0.9.1. The workspace validation lock instead uses
flate2 1.1.9/miniz_oxide0.8.9; these measurements do not describe that other
binary. The historical consumer lock changed only the local package version
5.2.0 to5.3.0. No dependencies were updated in the product.

## Hallazgos

1. **Test fixtures outside the crate (resolved)**: `oxidize-pdf-core/tests/issue_661_writer_resources_test.rs:101` — the initial test used an external include path. It now uses the bundled SourceSans3 TTF and a licensed, renamed CJK fixture inside the crate. The CJK generator/hash/source provenance are included; regeneration is byte-identical. The312,272-byte fixture retains1024 real ideographs plus the test characters to exercise automatic CFF subsetting, as the original16.5MB source does. It does not use padding. External legacy/modern checks also pass with these final fixtures.
2. **Minimum PDF byte size rejects successful optimization (resolved)**: `oxidize-pdf-core/tests/memory_optimization_integration.rs:251` — a minimum20KB proxy failed despite complete output. It was replaced with checks of all25 pages and all46 lines/page through both save/to_bytes; upper size/time guards remain. The initial failure and final7/7 target results are retained.
3. **Small whole OpenType/CFF programs carry a mismatched subtype (separate blocked finding)**: `oxidize-pdf-core/src/writer/pdf_writer/mod.rs:1468` — a3328-byte CJK input bypasses the pre-existing subsetting threshold; its OTTO wrapper is embedded under CIDFontType0C. Poppler warns on both the candidate and a retained release5.3.0 control; extracted Unicode matches in both. This font-program path is unchanged by the resource optimization. The small font, PDFs, command output and control binary identity remain in `small-cff-probe/`. No correction is made without a dedicated open issue; maintenance owns creation/linking. This does not block resource sharing because the warning is unchanged in the control and final representative subsetting outputs have no warning. It is not silently accepted as a passing external fixture.

No unresolved finding remains in the changed resource-sharing path. Product files
modified by the final review:0; two test-quality findings were corrected and
revalidated. Automatic scanner notices were checked manually: match branches
return values, unwraps fail tests on errors, and constants encode independent
PDF/name expectations.

The other profiling opportunities were evaluated without weakening contracts:
standard-font tracking also feeds custom registrations sharing those names,
so removing it requires a separate compatibility-preserving representation.
Compression changes remain a CPU/size tradeoff; the default and backend remain
unchanged. Formatting/page copies remain lower-priority opportunities from the
historical profile. These do not prevent accepting the measured resource work;
no performance claim extends to them. Imported-only documents do not share
font resources in this change; images and font-program construction costs are
not optimized. No guarantee of matching another library's throughput is made.
