# Issue #712 — DocMDP for notes and highlights

## Outcome and scope

Nonempty incremental text-note and highlight batches now call the same certification
policy validator already used by FreeText/Ink/Geometric editors. P1/P2 deny annotation
mutations; P3 and ordinary approval signatures permit them. Shared helper lives in
incremental_annotations; no public API, serialization algorithm or dependency changes.
Reads and empty batches retain their behavior. Input/batch validation still runs before
the policy check, and no incremental object is allocated before permission succeeds.

## Validation

RED: five failures and one passing allowed-policy control. GREEN: all six new tests
pass, plus 37 related notes/highlights/DocMDP/FreeText regressions. Three normally ignored
qpdf interoperability tests were explicitly run and pass. Library: 6809 pass, three
existing ignored. Scoped Clippy with warnings denied and changed-file rustfmt pass.

Tests cover adding, note update/removal, highlight removal, reads, empty batches,
P1/P2 rejection, P3/approval lifecycles, orphan certification transforms and the original
signed P2 fixture. Synthetic policy variants are policy tests, not authenticity claims.
The assertion helper discards successful PDF payloads before reporting an unexpected
success, avoiding dumping whole PDFs in future failure logs. RED evidence predates that
diagnostic-only change; stored logs omit giant Debug byte arrays but retain failures.

## Quality review

Kripteia Rust scans 10433 tests / 762 files, score 94; the new six tests score 100.
Manual review verifies that both public entry points call the gate once per nonempty
batch, before writer creation, and use IncrementalModification::AddAnnotation for all
annotation mutations, consistent with existing FreeText behavior. The policy parser
is unchanged; its ambiguity/redefinition tests remain in the related #532 regression.
No assertion was weakened to make the new policy pass. Adjacent FreeText/Ink/Geometric,
OCR and tagged-PDF editors already invoke certification checks.

## Security review

Kripteia reports a preexisting example path-to-fs::read flow (text_content_probe.rs,
caller-selected local file by design) and ten preexisting unsafe test allocator methods.
None is changed or newly reachable by this patch. No new unsafe, file I/O or public
attack surface. The fix closes the confirmed policy bypass without reimplementing the
private validator in language bindings. No unresolved finding in this patch.
