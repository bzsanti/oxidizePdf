## Hallazgos

1. El primer candidato no aportaba el codespace efectivo de Identity-H por
   diccionario. El control `named_identity_dictionary_supplies_unicode_codespace`
   falló por aserción; se corrigió usando el mapa Identity construido, y pasó.
2. Reinterpretar un nombre PDF como texto PostScript permitiría que nombres
   escapados alterasen el mapa. Se eliminó la conversión: el nombre se conserva
   como dato. El control escapado verifica que no inyecta una regla bfchar.
3. La API preexistente del extractor omite errores al cargar fuentes; los
   controles strict de padres inválidos alcanzan directamente el parser real,
   pero no prueban ni prometen propagación de ese error desde extracción de página.
   Cambiar dicha política queda fuera de estas dos correcciones.
