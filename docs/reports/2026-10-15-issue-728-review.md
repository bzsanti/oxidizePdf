# Revisión #728 — StreamingPdfWriter — 2026-10-15

## Resumen ejecutivo

Issue OPEN #728, finding 9 de #719. Implementación sobre develop 7e5799e7; integración posterior con develop 207ac996 tras #759, con único conflicto en TASKS.md. Fuentes finales identificadas por SHA256 en `2026-10-15-issue-728-evidence/source-manifest.json`. Rust 2021, MSRV 1.88, biblioteca síncrona; feature performance implica compression. Sin dependencias ni unsafe nuevos.

El escritor alternativo emitía streams dentro del diccionario de una página, reutilizaba IDs reservados, estimaba Kids y contaba solo algunos bytes. Ahora cada objeto está completo antes del siguiente; un contador privado registra todas las escrituras formateadas/binarias; páginas y streams usan referencias asignadas; catálogo 1 y Pages 2 quedan reservados. xref_streaming selecciona un stream binario [1,8,2] con su propia entrada, o una tabla clásica de offsets de diez dígitos. La finalización válida implica flush, sin prometer publicación atómica ni fsync.

El estado rechaza escritura tras finalización o fallo I/O. Recursos que la API no puede registrar, MemoryMapped y callbacks sin API se rechazan explícitamente. Direct usa realmente capacidad de buffer cero; Buffered conserva el buffer configurado. Se corrige la estadística de bytes y se documenta el crecimiento de índices y el coste temporal de compresión. El ejemplo usa gráficos autocontenidos, sin referencias a fuentes inexistentes.

Revisión del alcance completada, sin bloqueantes funcionales locales. Clippy predeterminado estricto y Clippy de biblioteca/contratos con performance pasan; la pasada ampliada all-targets/performance falla por dos lints preexistentes del ejemplo, detallados abajo. No se presenta esa pasada como verde. CI del nuevo PR pendiente.
